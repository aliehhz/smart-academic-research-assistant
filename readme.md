دستیار پژوهشی آکادمیک هوشمند
دستیار پژوهشی آکادمیک هوشمند پروژه‌ای پایتونی برای کار با مقاله‌های پژوهشی است که مسیر پاسخ‌گویی مبتنی بر بازیابی متن (RAG) را از مسیر خلاصه‌سازی کل سند جدا می‌کند. هدف، فراهم‌کردن بستری ماژولار برای پرسش‌وپاسخ درباره محتوای مقاله و تولید خلاصه‌ای متکی بر متن منبع است.
وضعیت پروژه: در حال توسعه (Work in Progress). این مخزن نسخه‌ای اولیه و در حال تکمیل است؛ ساختار و رفتار بعضی بخش‌ها هنوز تغییر می‌کند و نباید آن را محصول نهایی یا سامانه‌ای کاملاً ارزیابی‌شده در نظر گرفت.
نام مخزن: smart-academic-research-assistantزبان پیاده‌سازی: Pythonنسخهٔ پیشنهادی Python: 3.10 یا بالاتر
قابلیت‌ها و معماری فعلی
ساختار پروژه به ماژول‌های جداگانه تقسیم شده تا پردازش فایل، بازیابی اطلاعات و تولید پاسخ مستقل‌تر توسعه یابند. بر اساس اجزای فعلی پروژه، این بخش‌ها در نظر گرفته شده‌اند:
ورود و پردازش سند: pdf_reader.py برای خواندن PDF و ingest.py برای آماده‌سازی ورودی‌ها.
تقسیم متن: chunker.py برای تبدیل متن سند به بخش‌های کوچک‌تر مناسب بازیابی.
نمایه‌سازی برداری: vector_store.py و پوشهٔ محلی chroma_db/ برای نگه‌داری و بازیابی داده‌های برداری.
پرسش‌وپاسخ مبتنی بر بازیابی: rag_chain.py برای بازیابی قطعه‌های مرتبط و ساخت پاسخ بر اساس زمینهٔ بازیابی‌شده.
خلاصه‌سازی سند: summarizer.py برای مسیر خلاصه‌سازی که از پرسش‌وپاسخ مبتنی بر چند قطعه متمایز است.
هدایت درخواست: router.py و main.py برای تشخیص مسیر مناسب و اجرای برنامه.
ارتباط با مدل زبانی و تنظیمات: llm_service.py و config.py برای بخش‌های مرتبط با مدل و پیکربندی.
جزئیات دقیق رفتار هر ماژول به نسخهٔ کد وابسته است؛ README با پیشرفت پیاده‌سازی به‌روزرسانی خواهد شد.
پیش‌نیازها و راه‌اندازی
برای اجرای پروژه به Python 3.10 یا بالاتر، Git و وابستگی‌های ثبت‌شده در requirements.txt نیاز دارید. اگر مسیر تولید پاسخ از Gemini استفاده کند، دسترسی شبکه و کلید API معتبر نیز لازم است. برای راهنمای رسمی راه‌اندازی Gemini API و SDK پایتون، مستندات آغاز کار Google AI را ببینید.
در PowerShell ویندوز، پس از دریافت مخزن، از پوشهٔ اصلی پروژه اجرا کنید:
git clone https://github.com/USERNAME/smart-academic-research-assistant.git
cd smart-academic-research-assistant

py -3.10 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt

در لینوکس یا macOS، ساخت و فعال‌سازی محیط مجازی به این شکل است:
git clone https://github.com/USERNAME/smart-academic-research-assistant.git
cd smart-academic-research-assistant
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt

USERNAME را با نام کاربری GitHub و نشانی مخزن واقعی جایگزین کنید. پیش از اجرا، شیوهٔ تنظیم کلید و نام متغیرهای محیطی را با config.py و مستندات همان نسخهٔ پروژه تطبیق دهید؛ نام متغیر مشخصی در این README حدس زده نشده است. کلید را در کد یا مخزن عمومی قرار ندهید. پس از تنظیم پیکربندی، نقطهٔ شروع فعلی پروژه main.py است:
python main.py

ممکن است لازم باشد PDF ورودی را در مسیر مورد انتظار کد قرار دهید. چون مسیر ورودی و رابط خط فرمان در نسخه‌های در حال توسعه تغییرپذیرند، برای جزئیات عملیاتی به config.py و main.py همان نسخه رجوع کنید.
نحوه استفاده و ملاحظات پاسخ‌گویی
در طرح فعلی، درخواست‌هایی که دربارهٔ یک موضوع یا بخش مشخص از مقاله هستند باید از مسیر RAG استفاده کنند: سیستم قطعه‌های مرتبط را بازیابی می‌کند و پاسخ را با اتکا به همان زمینه می‌سازد. درخواست خلاصهٔ کل مقاله باید به مسیر خلاصه‌سازی سند هدایت شود؛ بازیابی چند قطعه به‌تنهایی معادل خواندن و خلاصه‌کردن کل متن نیست.
این تفکیک برای کاهش پاسخ‌های ناقص یا نامستند اهمیت دارد. اگر متن بازیابی‌شده برای پاسخ کافی نباشد، سامانه باید این محدودیت را آشکار کند، نه اینکه جزئیات مقاله را حدس بزند. با این حال، تشخیص نیت و انتخاب مسیر در نسخهٔ فعلی هنوز نیازمند آزمون و بهبود است؛ از جمله عبارت‌های کامل درخواست خلاصه ممکن است همیشه درست تشخیص داده نشوند. پاسخ مدل را با متن اصلی مقاله بررسی کنید، به‌ویژه برای استفادهٔ دانشگاهی یا استناد علمی. این پروژه جایگزین بررسی منبع اولیه نیست.
وضعیت توسعه و مسیر پیش‌رو
پروژه فعالانه در حال تکمیل است و هنوز نسخهٔ پایدار یا انتشار رسمی ندارد. قابلیت‌ها، رابط اجرا و تنظیمات ممکن است تغییر کنند؛ بنابراین مخزن را نمونهٔ کار و بستر توسعه بدانید، نه نرم‌افزار آمادهٔ استفادهٔ پژوهشی بدون بازبینی.
محورهای پیشنهادی برای ادامهٔ توسعه عبارت‌اند از:
بهبود تشخیص نیت برای تفکیک مطمئن خلاصه‌سازی، پرسش‌وپاسخ و درخواست‌های مبهم؛
اجرای تشخیص نیت محلی و سبک برای کاهش وابستگی این مرحله به سرویس آنلاین؛
تکمیل مسیر خلاصه‌سازی کل سند، از جمله دسترسی پایدار به متن کامل استخراج‌شده؛
افزودن آزمون‌های خودکار برای پردازش PDF، بازیابی، مسیریابی و مدیریت خطا؛
بهبود ارزیابی وفاداری پاسخ به متن و مستندسازی تنظیمات و نمونه‌های اجرا.
این موارد برنامهٔ توسعه‌اند و نباید به‌عنوان قابلیت کامل‌شدهٔ نسخهٔ فعلی تلقی شوند.
امنیت و مشارکت
پیش از عمومی‌کردن مخزن، مطمئن شوید هیچ کلید API، فایل .env، سند دارای محدودیت انتشار یا دادهٔ خصوصی در Git ثبت نشده است. .gitignore باید دست‌کم محیط مجازی، فایل‌های محیطی، کش Python و داده‌های محلی قابل‌بازسازی مانند chroma_db/ را پوشش دهد. پوشهٔ data/ را فقط پس از بررسی مجوز و محتوای فایل‌هایش عمومی کنید. اگر فایلی پیش‌تر commit شده باشد، افزودن آن به .gitignore به‌تنهایی آن را از تاریخچهٔ Git حذف نمی‌کند.
برای مشارکت، ابتدا وضعیت مخزن و راهنمای تنظیمات را بررسی کنید؛ سپس تغییرات کوچک و مشخص را همراه با توضیح، آزمون مرتبط و به‌روزرسانی مستندات ارائه دهید. پیش از انتشار عمومی، git status و محتوای فایل‌های آمادهٔ commit را بازبینی کنید. تا زمانی که مجوزی به مخزن افزوده نشده، مجوز استفاده یا بازتوزیع خاصی را مفروض نگیرید.
